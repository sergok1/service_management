# Управление сервисами

Набор bash-скриптов для управления системными сервисами и оптимизации их ресурсопотребления в Linux.

## Описание

Некоторые фоновые сервисы могут потреблять значительные системные ресурсы:
- **CPU** — высокая нагрузка в многопоточном режиме
- **RAM** — потребление до нескольких гигабайт
- **I/O** — интенсивные операции чтения/записи

Это приводит к снижению производительности и отзывчивости системы. Данный набор инструментов позволяет гибко управлять такими сервисами: временно отключать, включать обратно, ограничивать потребление ресурсов через systemd, а также контролировать, что отключённые сервисы не были запущены повторно.

## Состав репозитория

| Файл | Назначение |
|------|-----------|
| `services.conf` | Единый список управляемых сервисов |
| `disable_services.sh` | Остановка, отключение автозапуска и маскировка сервисов |
| `enable_services.sh` | Снятие маски, включение автозапуска и запуск сервисов |
| `apply_resource_limits.sh` | Применение ограничений CPU/RAM/IO через systemd drop-in |
| `remove_systemd_overrides.sh` | Удаление ограничений с созданием резервных копий |
| `watchdog.sh` | Периодическая проверка, что сервисы остаются отключёнными |
| `watchdog.conf` | Конфигурация watchdog (паттерны процессов, уведомления) |
| `install_watchdog.sh` | Установка watchdog как systemd timer |
| `uninstall_watchdog.sh` | Полное удаление watchdog |
| `systemd/` | Unit-файлы для watchdog timer |

## Быстрый старт

```bash
git clone git@github.com:sergok1/service_management.git && cd service_management
chmod +x *.sh
```

### Отключение сервисов

```bash
sudo ./disable_services.sh
```

Скрипт остановит сервисы (с таймаутом, при необходимости — принудительно через SIGKILL), отключит автозапуск, замаскирует их и проверит, что процессы завершены. Сервисы с unit-файлами в `/etc/systemd/system/` автоматически перемещаются в бэкап перед маскировкой.

### Включение сервисов

```bash
sudo ./enable_services.sh
```

Скрипт снимет маску, восстановит unit-файлы из бэкапа (если были перемещены), включит автозапуск, запустит сервисы и проверит, что они не упали после старта.

### Ограничение ресурсов

Если полное отключение нежелательно, можно ограничить потребление ресурсов:

```bash
sudo ./apply_resource_limits.sh
```

Скрипт создаёт systemd drop-in override для каждого сервиса с настройками `CPUQuota`, `CPUWeight`, `MemoryMax`, `MemoryHigh`, `Nice`, `IOWeight` и др.

### Откат ограничений

```bash
sudo ./remove_systemd_overrides.sh
```

Скрипт удалит override-файлы, предварительно сохранив резервные копии. Старые бэкапы автоматически ротируются (хранятся последние 5).

## Watchdog

Watchdog периодически проверяет, что отключённые сервисы не были запущены повторно (вручную, обновлением пакетов, другим пользователем и т.д.).

### Что проверяет

- Все сервисы из `services.conf` замаскированы и не запущены
- Нет процессов от управляемых агентов (паттерны в `watchdog.conf`)
- Нет активных сессий других пользователей
- Не появились новые подозрительные systemd-юниты
- Нет сетевых портов, открытых агентами

### Установка

```bash
sudo ./install_watchdog.sh
```

Копирует файлы в `/opt/services_management/`, создаёт systemd timer (каждые 60 минут + через 2 минуты после загрузки) и запускает тестовую проверку.

### Ручной запуск

```bash
sudo /opt/services_management/watchdog.sh          # только проверка
sudo /opt/services_management/watchdog.sh --fix    # проверка + автоисправление
```

Флаг `--fix` автоматически маскирует размаскированные сервисы и завершает обнаруженные процессы агентов.

### Приостановка / возобновление

```bash
sudo systemctl stop services-watchdog.timer     # приостановить
sudo systemctl start services-watchdog.timer    # возобновить
```

### Полное удаление

```bash
sudo ./uninstall_watchdog.sh
```

Останавливает таймер, удаляет systemd-юниты и `/opt/services_management/`. Лог остаётся в `/var/log/services_management_watchdog.log`.

## Конфигурация

### services.conf

Список сервисов — по одному на строку. Порядок важен:
- `enable_services.sh` обрабатывает сверху вниз
- `disable_services.sh` обрабатывает снизу вверх

Поэтому `.service` должен идти перед соответствующим `.timer` — при включении сервис восстанавливается раньше, чем таймер попытается его триггерить.

Все скрипты (кроме `apply_resource_limits.sh`) читают `services.conf` автоматически.

### apply_resource_limits.sh

Конфигурация лимитов задаётся внутри скрипта, так как каждый сервис имеет индивидуальные параметры.

### watchdog.conf

Паттерны процессов для поиска, имя пользователя-владельца (для проверки чужих сессий), настройки десктоп-уведомлений.

Чтобы добавить или убрать сервис — отредактируйте `services.conf` и, при необходимости, `watchdog.conf` и массив `configs` в `apply_resource_limits.sh`.

## Логирование

| Лог | Источник |
|-----|---------|
| `/var/log/services_management.log` | `disable_services.sh`, `enable_services.sh` и другие скрипты управления |
| `/var/log/services_management_watchdog.log` | `watchdog.sh` |

Каждая запись содержит временную метку и результат операции.

## Требования

- Linux с systemd (cgroups v2)
- Права root (sudo)
- bash 4+ (для `mapfile` и ассоциативных массивов)
- `notify-send` (опционально, для десктоп-уведомлений watchdog)

## Безопасность и восстановление

- Все скрипты проверяют наличие прав root перед выполнением
- Проверяется существование юнита перед любой операцией
- `disable_services.sh` использует таймаут на остановку с fallback на SIGKILL
- Unit-файлы из `/etc/systemd/system/` перемещаются в `/var/lib/services_management/unit_backups/` перед маскировкой и автоматически восстанавливаются при включении
- `enable_services.sh` проверяет, что сервис не упал после запуска
- `apply_resource_limits.sh` проверяет, что сервис не упал после применения лимитов
- `remove_systemd_overrides.sh` создаёт резервные копии и ротирует старые
- Watchdog с флагом `--fix` автоматически восстанавливает маскировку при обнаружении нарушений

Восстановление ограничений из бэкапа:

```bash
sudo cp /root/systemd_override_backups_<timestamp>/<service>.service.d/override.conf \
  /etc/systemd/system/<service>.service.d/override.conf
sudo systemctl daemon-reload
sudo systemctl restart <service>
```
